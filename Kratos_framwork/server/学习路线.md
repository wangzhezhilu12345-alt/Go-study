# Kratos 学习路线

这份文档不是讲一套抽象概念，而是带你按照当前这个 `server` 项目来学 Kratos。

如果你现在是第一次认真接触 Kratos，最重要的一句话是：

先学会把项目跑起来，再学目录分层，再学 proto 生成，再学中间件和 JWT。

---

## 一、你现在手里的这个项目是什么

当前目录 [server](/c:/Users/31388/Desktop/its%20mygo/Kratos_framwork/server) 是一个标准 Kratos 风格项目，里面已经有这些典型结构：

- [cmd/server](/c:/Users/31388/Desktop/its%20mygo/Kratos_framwork/server/cmd/server)：程序入口
- [api](/c:/Users/31388/Desktop/its%20mygo/Kratos_framwork/server/api)：proto 接口定义和生成代码
- [internal/service](/c:/Users/31388/Desktop/its%20mygo/Kratos_framwork/server/internal/service)：接口实现层
- [internal/biz](/c:/Users/31388/Desktop/its%20mygo/Kratos_framwork/server/internal/biz)：业务逻辑层
- [internal/data](/c:/Users/31388/Desktop/its%20mygo/Kratos_framwork/server/internal/data)：数据访问层
- [internal/server](/c:/Users/31388/Desktop/its%20mygo/Kratos_framwork/server/internal/server)：HTTP / gRPC 服务注册
- [configs](/c:/Users/31388/Desktop/its%20mygo/Kratos_framwork/server/configs)：配置文件

你可以先把它理解成：

- `cmd` 负责启动
- `api` 负责定义接口
- `service` 负责接请求
- `biz` 负责写业务
- `data` 负责拿数据
- `server` 负责把服务挂到 HTTP / gRPC 上

## 二、最推荐的学习顺序

### 第 1 步：先把项目跑起来

先不要急着改代码，先确认自己知道“Kratos 项目怎么启动”。

在终端中进入：

```powershell
cd c:\Users\31388\Desktop\its mygo\Kratos_framwork\server
go run ./cmd/server -conf ./configs
```

启动成功后，你会看到：

- HTTP 监听 `8000`
- gRPC 监听 `9000`

然后访问：

```powershell
curl http://127.0.0.1:8000/helloworld/abc
```

如果返回 `Hello abc`，说明你已经完成了第一阶段。

这一阶段你真正要学会的不是“为什么这么设计”，而是：

- Kratos 项目从哪里启动
- 默认跑起来后有哪些端口
- HTTP 接口在哪里注册的

## 三、第二步看启动流程

这一部分建议你按下面顺序读代码。

### 1. 先看入口

先看 [main.go](/c:/Users/31388/Desktop/its%20mygo/Kratos_framwork/server/cmd/server/main.go)。

你要重点看这几件事：

- 配置文件怎么加载
- `wireApp(...)` 是怎么创建应用的
- `kratos.New(...)` 是怎么把 HTTP 和 gRPC 服务装进去的

你可以把它理解为：

`main.go` 负责把整个项目“拼起来并启动”。

### 2. 再看依赖注入

然后看：

- [wire.go](/c:/Users/31388/Desktop/its%20mygo/Kratos_framwork/server/cmd/server/wire.go)
- [wire_gen.go](/c:/Users/31388/Desktop/its%20mygo/Kratos_framwork/server/cmd/server/wire_gen.go)

这里你先不用死扣 Wire 的语法，先只看结果：

- 它把 `data`、`biz`、`service`、`server` 串起来了

你只要先明白：

Kratos 项目经常不是你手动 `new` 一堆对象，而是交给 Wire 自动组装。

## 四、第三步看一个请求是怎么走的

这一步是 Kratos 入门最关键的一步。

建议你先只跟默认的 `Greeter` 这条链路，不要一开始就跟你自己的 `server.proto`。

### 建议按这个顺序看

1. [greeter.proto](/c:/Users/31388/Desktop/its%20mygo/Kratos_framwork/server/api/helloworld/v1/greeter.proto)
2. [greeter_http.pb.go](/c:/Users/31388/Desktop/its%20mygo/Kratos_framwork/server/api/helloworld/v1/greeter_http.pb.go)
3. [http.go](/c:/Users/31388/Desktop/its%20mygo/Kratos_framwork/server/internal/server/http.go)
4. [greeter.go](/c:/Users/31388/Desktop/its%20mygo/Kratos_framwork/server/internal/service/greeter.go)
5. [greeter.go](/c:/Users/31388/Desktop/its%20mygo/Kratos_framwork/server/internal/biz/greeter.go)
6. [greeter.go](/c:/Users/31388/Desktop/its%20mygo/Kratos_framwork/server/internal/data/greeter.go)
### 你要看懂的链路

请求流程其实是这样：

1. 浏览器访问 `/helloworld/{name}`
2. HTTP 路由被生成代码接住
3. `GreeterService` 的 `SayHello` 被调用
4. `service` 调用 `biz`
5. `biz` 再调用 `data`
6. 返回结果给前端

如果你能把这条链路说清楚，你就已经真正开始入门 Kratos 了。

---

## 五、第四步学 proto

Kratos 一个很核心的点是：接口通常不是先手写路由，而是先写 `proto`。

你现在手里已经有两个很好的学习样本：

- [greeter.proto](/c:/Users/31388/Desktop/its%20mygo/Kratos_framwork/server/api/helloworld/v1/greeter.proto)
- [server.proto](/c:/Users/31388/Desktop/its%20mygo/Kratos_framwork/server/api/server/server.proto)

### 先学什么

先看这几个点：

- `package` 是什么
- `option go_package` 是什么
- `service` 是什么
- `message` 是什么
- HTTP 注解在什么地方写

### 你要特别注意

[server.proto](/c:/Users/31388/Desktop/its%20mygo/Kratos_framwork/server/api/server/server.proto) 现在只有 gRPC 定义，没有 HTTP 注解，所以它虽然能生成 gRPC 服务代码，但不会像 `Greeter` 一样自动暴露 HTTP 路由。

这就是一个很好的学习点：

- 有 HTTP 注解，就能生成 HTTP 路由
- 没有 HTTP 注解，就只有 gRPC

---

## 六、第五步学代码生成

Kratos 学习中，很多人第一次卡住就是卡在“我改了 proto，为什么项目没变化”。

因为 proto 改完后，你还要重新生成代码。

当前这个项目里，你以后最常用的命令是：

```powershell
cd c:\Users\31388\Desktop\its mygo\Kratos_framwork\server
go generate ./...
go build ./...
```

如果你改的是 `proto`，也可以用：

```powershell
make api
```

你可以先把代码生成理解成：

- `proto` 是接口设计稿
- `.pb.go` / `_grpc.pb.go` / `_http.pb.go` 是自动生成的桥梁代码

---

## 七、第六步学分层

等你能看懂一个请求怎么走之后，就开始认真理解分层。

### `service` 层

看 [internal/service](/c:/Users/31388/Desktop/its%20mygo/Kratos_framwork/server/internal/service)。

它主要负责：

- 接收请求
- 调用业务层
- 返回响应

它不应该塞太多复杂业务细节。

### `biz` 层

看 [internal/biz](/c:/Users/31388/Desktop/its%20mygo/Kratos_framwork/server/internal/biz)。

它主要负责：

- 写业务规则
- 定义仓储接口
- 组织业务逻辑

它是项目里最接近“真实业务”的地方。

### `data` 层

看 [internal/data](/c:/Users/31388/Desktop/its%20mygo/Kratos_framwork/server/internal/data)。

它主要负责：

- 数据库存取
- 调用外部服务
- 实现 `biz` 层定义的 repo 接口

你可以简单记：

- `service` 是对外
- `biz` 是核心
- `data` 是对内拿数据

等你把默认 `Greeter` 学顺以后，再回头看你自己加的 `Server` 服务。

重点看这些文件：

这一阶段你就开始从“会运行模板”进入“会加自己的服务”了。

## 九、第八步最后再学 JWT 和中间件

你现在还有一个 [JWT/test.go](/c:/Users/31388/Desktop/its%20mygo/Kratos_framwork/JWT/test.go)，它更适合放在这个阶段学。

因为这时候你已经知道：

- 请求怎么进入服务
- HTTP 和 gRPC 怎么启动
- `service` 怎么实现
- `proto` 怎么生成

这时再回头看：

- `jwt.Server(...)`
- `jwt.Client(...)`
- `Middleware(...)`

你会轻松很多。

否则一开始就看 JWT，会很容易把“框架结构问题”和“认证问题”混在一起。

## 十、最适合你的实操路线

如果你想真正学会，不要只看，最好按这个顺序自己动手：

1. 启动当前项目并访问 `/helloworld/abc`
2. 修改 `GreeterService` 的返回内容，确认自己能改出效果
3. 修改 `greeter.proto`，重新生成代码，再重新运行
4. 给 `server.proto` 补上 HTTP 注解
5. 让 `ServerService` 同时支持 HTTP 和 gRPC
6. 再尝试加日志中间件
7. 最后再把 JWT 放进来

---

## 十一、你现在最该先完成的 3 件事

如果你问我“当前阶段最该先干嘛”，我的建议是：

1. 跑通默认 `Greeter` 接口，并确认自己知道请求链路怎么走
2. 看懂 `main.go`、`wire_gen.go`、`http.go`、`greeter.go`
3. 自己改一次 `proto` 并重新生成代码

只要这三件事你完成了，Kratos 的入门就已经过线了。

等你把这份路线走完，你再继续学这些内容会比较稳：

- 服务注册发现

## 十三、一句话总结

Kratos 不难，难的是一开始概念太多。

你只要记住这条主线：

先跑起来 -> 再看请求链路 -> 再学 proto 生成 -> 再学分层 -> 最后再学 JWT 和中间件

按这个顺序走，你会学得很扎实。
